# PostgreSQL and Alembic for DX-Farm

Use PostgreSQL as the durable store for structured knowledge, RAG documents, workflow cases/events and applied-treatment PHI.

## Prerequisites

- Docker Compose v2 and Python 3.11+.
- `deploy/docker-compose.yml` defaults to PostgreSQL 15 with database/user/password `dxfarm` on port `5432`.
- RAG migration requires extension `vector`; the committed `postgres:15-alpine` image does not bundle pgvector, so use a PostgreSQL image/server with pgvector before running the full AI migration chain.

## Start and connect

```bash
cd /path/to/DX---Farm
cp deploy/.env.example deploy/.env
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d postgres
docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps
cd ai
cp .env.example .env
```

`ai/.env` must contain a URL matching `deploy/.env`, by default:

```dotenv
DATABASE_URL=postgresql+psycopg://dxfarm:dxfarm@localhost:5432/dxfarm
```

Check a running database with:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Useful SQL: `\conninfo`, `\dt`, `\dx`, `SELECT version_num FROM alembic_version;`.

## Migration and seed order

```bash
cd ai
python3 -m venv venv
source venv/bin/activate
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m alembic current
python -m scripts.seed_diseases
python -m scripts.seed_pesticides
python -m scripts.seed_treatment_rules
python -m scripts.seed_disease_management_policies
```

Current Alembic head is `f0a1b2026011`; the seeders are idempotent and must run in the displayed order.

Run RAG embedding only when intended:

```bash
python -m scripts.ingest_diseases --dry-run --limit 3
python -m scripts.ingest_diseases
```

The non-dry command creates embeddings and replaces the disease corpus; it is not needed merely to add JSON data files.

## New migration

```bash
cd ai
source venv/bin/activate
python -m alembic revision --autogenerate -m "short_description"
# inspect revision: no unintended drop_table/drop_column
python -m alembic upgrade head
python -m alembic check
```

Do not edit an applied revision.
This database is shared with Spring models in development, so inspect autogenerated changes carefully and remove operations outside the AI-owned change.

## Recovery and common errors

| Symptom | Action |
|---|---|
| connection refused | Check `docker compose ... ps`, then `logs postgres`; wait for `healthy`. |
| relation already exists | Do not `stamp head`; inspect whether another schema tool created it. |
| `type vector does not exist` | Use a pgvector-enabled PostgreSQL instance and rerun migration. |
| PyPI read timeout | Retry `python -m pip install --default-timeout=120 --retries 10 -r requirements.txt`. |

`alembic downgrade` can remove schema/data; use it only on a disposable local database after reviewing the revision.
